# bonYe! وب‌اپ مشتریان

وب‌اپ Flutter با همان صفحات، برند، فارسی/انگلیسی و API اپ اندروید. پوشه، گیت و تنظیمات انتشار مستقل؛ حساب، پت‌ها و خریدهای مشتری از API مشترک خوانده می‌شوند.

## توسعه مشترک

منبع اصلی قابلیت‌ها `hpeikanian/bonyeapp` است. کد Flutter این ریپوزیتوری یک snapshot از همان منبع است، نه یک پیاده‌سازی مستقل. تغییرات قابلیت‌ها باید در منبع اصلی انجام شوند، سپس:

```sh
python3 tool/sync_source.py /workspace/bonyeapp
flutter pub get --enforce-lockfile
flutter analyze
flutter test
./tool/build_web.sh
```

`source-revision.json` نسخه و اثر انگشت کد مشترک را ثبت می‌کند. گردش کار GitHub Actions با هر push این پروژه، اجرای دستی، repository_dispatch و بررسی ساعتی، جدیدترین main اندروید را دریافت و وب را تست و build می‌کند. این گردش کار خروجی Artifact تولید می‌کند؛ انتشار خودکار روی هاست هنوز تنظیم نشده است. زمان‌بندی GitHub ممکن است تأخیر داشته باشد. برای مخزن منبع خصوصی، secret با نام `BONYE_SOURCE_TOKEN` و دسترسی فقط خواندن آن مخزن لازم است؛ توکن داخل سورس قرار نگیرد.

## ساخت و نصب روی سایت

Flutter 3.29.3 / Dart 3.7.2. خروجی پیش‌فرض برای `https://bonye.pet/app/` ساخته می‌شود:

```sh
./tool/build_web.sh
```

محتویات `build/web/`، شامل `.htaccess`، در پوشه `app` هاست کپی شود؛ فایل‌های WordPress یا نرم‌افزار اصلی جایگزین نشوند. HTTPS لازم است. روی Safari: Share → Add to Home Screen. روی اندروید نیز نصب مرورگری ممکن است.

برای مسیر دیگر: `BONYE_WEB_BASE_PATH=/chosen-path/ ./tool/build_web.sh`. دامنه API همچنان `https://bonye.pet/totallsystem/api/v1` است. میزبانی روی همان دامنه، مشکل CORS را حذف می‌کند. برای دامنه دیگر، تنظیم CORS سرور با مبدأ مشخص و هدرهای Authorization، Content-Type و Idempotency-Key لازم است.

## پادکست و آفلاین

نسخه وب صوت و متادیتای عمومی پادکست را در Cache Storage مرورگر ذخیره می‌کند؛ اطلاعات حساب و پیشرفت شنیدن وارد این کش نمی‌شود. دانلود وب حداکثر ۶۴ مگابایت است. مرورگر می‌تواند فایل‌های آفلاین را پاک کند. دانلود صوت از دامنه دیگر نیازمند CORS آن میزبان است. پخش پس‌زمینه و اعلان رسانه روی آیفون وابسته به Safari و نسخه سیستم است و تضمین اپ بومی را ندارد.

Service Worker فقط فهرست مشخص فایل‌های پوسته را کش می‌کند؛ API، ورود، پرداخت و اطلاعات مشتری کش نمی‌شوند. اطلاعات زنده اینترنت می‌خواهد. نسخه جدید پس از بسته شدن تب‌های نسخه قدیمی فعال می‌شود. فایل‌های index، bootstrap و sw باید با no-cache سرو شوند. فایل‌های wasm با MIME صحیح سرو شوند.

## وضعیت اعتبارسنجی

نتایج اجرای واقعی در `docs/validation.json` ثبت می‌شوند. آماده بودن خروجی build به معنی نصب روی هاست یا تأیید ورود و خرید واقعی نیست. آزمون روی آیفون واقعی پس از میزبانی HTTPS لازم است.
